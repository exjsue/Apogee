# Decisions

| Date | Decision | Reason |
|------|----------|--------|
| 2026-10-22 | Web app only for now, plain HTML/CSS/JavaScript, no frameworks. | Owner is a beginner and wants the simplest path to a working app; iOS native deferred. |
| 2026-10-22 | All data stored on-device in IndexedDB. No server, no accounts, no analytics. | Privacy-first product goal. |
| 2026-10-22 | Browser storage is not the sole copy of user data; export/import is required in v1. | persist() returned false in iPhone Safari and Firefox Focus during a one-off test, so data can be evicted. |
| 2026-10-22 | Primary test browsers: iPhone Safari and Firefox Focus. | Owner uses Firefox Focus daily; Safari is the iPhone default and uses the same WebKit engine as every iOS browser, so it is the baseline. |
| 2026-10-22 | Weights stored as entered (value plus unit), converted only for display and calculation. | Converting kg to lb and back with floating-point math drifts, and rounding on save would permanently change what the user typed. |
| 2026-10-22 | ES modules need HTTP(S) serving, not file://. | Browsers block module loading from local files. |
| 2026-10-22 | crypto.randomUUID() needs a secure context and must be verified on iPhone Safari and Firefox Focus. | It is unavailable on plain HTTP pages. |
| 2026-10-22 | Storage is split into rules (src/storage/store.js) and adapters (memory, IndexedDB) behind a small interface. | The rules can be tested in Node with no dependencies; only the thin IndexedDB adapter needs a browser to test. |
| 2026-10-22 | Saving a workout with its entries and sets, and deleting a workout, are each a single transaction. | All of it saves or none of it does, so a crash or error cannot leave orphaned entries or sets. |
| 2026-10-22 | No fake-IndexedDB library; the IndexedDB adapter is tested in a real browser page (tests/browser/index.html). | Keeps the dependency list empty, and a fake would not prove the real browsers behave. |
| 2026-10-22 | Saves check that referenced records exist (entry needs workout and exercise, set needs entry), inside the same transaction as the write. | Prevents dangling references; checking and writing in one transaction avoids a race between them. |
| 2026-10-22 | saveWorkoutWithDetails treats the lists as the workout's complete contents and deletes its stored entries and sets that are not in them. | Otherwise editing a workout and removing an exercise would leave the removed entry behind. |
| 2026-10-22 | Import is replace-everything and needs explicit confirmation (confirmReplace: true). No merge. | Merge semantics (duplicates, conflicts, deletions) are harder to reason about, and restoring a backup should be predictable. |
| 2026-10-22 | Import validates the whole file before any write, then applies it in one transaction. | A bad or damaged file cannot corrupt or half-replace existing data. |
| 2026-10-22 | Export has a plain-text form (exportToText) as a fallback for iOS download problems. Unverified on WebKit. | File downloads can misbehave on iOS; the text can be copied and saved by hand. Download and file picker still need testing on iPhone Safari and Firefox Focus. |
| 2026-10-22 | Import is strict: every field must be present, unknown fields are rejected, and each stored record must equal its file record exactly (non-canonical timestamps are rejected, nothing is defaulted). | An import must never invent or silently change values; a hand-edited or foreign file fails loudly instead. |
| 2026-10-22 | Import size limit is 50 MiB, counted in UTF-8 bytes, and is a parameter. | A 20-year heavy history is about 35-40 MB; the limit stops a wrong huge file from freezing the tab. Memory use on iPhone is unmeasured. |
| 2026-10-22 | Muscles are a fixed vocabulary of 18 ids (chest, front_delts, side_delts, rear_delts, biceps, triceps, forearms, traps, lats, upper_back, lower_back, abs, obliques, glutes, quads, hamstrings, calves, adductors). An exercise needs at least one primary muscle; unknown, duplicate and primary/secondary-overlapping muscles are rejected. | Free text would give "chest", "Chest" and "pecs" as three muscles, which breaks search, the later muscle diagram and importers. A fixed list is one mapping target. Adding an id later is safe; removing or renaming one needs a data migration. |
| 2026-10-22 | Equipment tags are a fixed vocabulary of 11 (barbell, dumbbell, kettlebell, ez_bar, machine, smith_machine, cable, resistance_band, bodyweight, bench, pull_up_bar). | Same reason as muscles: searchable, and a single target for importers. |
| 2026-10-22 | Exercise names and all notes are trimmed with whitespace runs collapsed to one space (so they are single-line). Names are limited to 80 characters, notes to 500, counted in characters. | Keeps stored text canonical and bounded; prevents "Squat" and " Squat " being different exercises. Multi-line notes would need a different rule. |
| 2026-10-22 | The page's Content-Security-Policy blocks all network access: default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'none'; img-src 'self' data:; base-uri 'none'; form-action 'none'. The dev server sends the same policy, and a test checks that they match. | Privacy-first: even a bug or a bad dependency cannot send data anywhere. A test also scans index.html and src/ for network APIs, markup injection, eval and off-origin links, with an empty allowlist. |
| 2026-10-22 | The built-in exercises (16 lifts, ids starting seed-) are stored in IndexedDB as ordinary records, and seeding is tracked by a seedVersion in meta: it runs only when the stored version is lower than the code's, adds missing ids only, and never overwrites. | Stored records are included in exports and imports, so a backup is complete. The version lets later releases add exercises without touching a user's edits. |
| 2026-10-22 | Blank or whitespace reps and weight are errors and never become 0; bodyweight is an explicit 0. Decimals accept "62.5" and "62,5" (a comma only with 1-2 digits after it); "1,500", "1.500,5", exponents, hex, Infinity and NaN are rejected. | JavaScript's Number("") is 0, which would silently log a bodyweight set. Ambiguous separators are rejected rather than guessed. |
| 2026-10-22 | An unfinished workout that started more than 12 hours ago (a parameter) is never continued silently: the Log tab offers Continue, Finish or Discard. Finish ends it at its last set, not at "now". Logging is blocked until it is resolved. | A forgotten workout from yesterday must not swallow today's sets or show a 20-hour duration. |
| 2026-10-22 | deleteSet removes an entry when its last set goes; discardWorkout refuses a finished workout; finishing a workout with no sets is refused. Each is one transaction. | No empty entries or orphans, and the discard path cannot erase history by accident. |
| 2026-10-22 | Weights are shown in the preferred unit (default lb, stored in meta); a set entered in the other unit shows the converted value with "entered X" beside it. Stored values never change. | Reinforces "stored exactly as entered"; the toggle is display only. The preference is not exported. |
| 2026-10-22 | The dev server uses a fixed port (8080) and refuses to start if it is taken, instead of choosing another. | IndexedDB is per origin, and an origin includes the port: another port would open an empty database and look like data loss. |
